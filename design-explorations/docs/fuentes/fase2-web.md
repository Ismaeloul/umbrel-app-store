## 1. Armazón y navegación

### 1.1 Arranque (`main.tsx`, `index.html`, `app/App.tsx`)

- `main.tsx`, en este orden: importa `styles/fonts.css`, `styles/tokens.css`, `styles/base.css`; `installThemeWatcher()` (`app/theme.ts`), `installViewportWatcher()` (`lib/viewport.ts`, publica `--kb` con el alto del teclado), `installShortcutListener()` (`app/shortcuts.ts`); `createRoot(#root).render(<App client={queryClient} />)`; `bootApi(queryClient)` (`api/boot.ts`) y, si devuelve `notice`, `toast(text, { tone, ms: 4000 })`; la PWA (`features/pwa/install.ts`) se pide con `import()` 3 s después de `load` en `requestIdleCallback`.
- `index.html`: `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover, interactive-widget=resizes-content">`, dos `<meta name="theme-color">` (light `#e5eef4`, dark `#081829`), `<link rel="manifest" href="/manifest.webmanifest">`, `apple-mobile-web-app-status-bar-style=black-translucent`. Un `<style>` en línea fija el fondo del tema antes del CSS y un `<script>` en línea aplica `data-theme`/`data-scheme`/`data-transparency` a `<html>` leyendo `localStorage['aceneo-tema']` y `['aceneo-transparencia']`. Otro `<script>` lanza `window.__aceBootstrap = fetch('/api/v1/bootstrap')` salvo con `?demo=1` o `file:`.
- `app/App.tsx`: `App({ client?, initialSearch? })` → `<StrictMode><QueryClientProvider><RouterProvider initialSearch onBeforeChange={saveScroll}><Shell/></RouterProvider></QueryClientProvider></StrictMode>`.

### 1.2 Router propio (`app/router.tsx`, `app/routes.ts`)

**Historial (History API), no hash.** Todo cuelga de `?vista=`; el pathname siempre es `/`.

| `?vista=` | `Route` (unión discriminada en `routes.ts`) |
|---|---|
| (vacío) · `agenda` | `{ vista: 'agenda' }` |
| `biblioteca` | `{ vista: 'biblioteca' }` |
| `buscar` | `{ vista: 'buscar' }` |
| `ajustes` · `ajustes/<sección>` | `{ vista: 'ajustes', seccion: string \| null }` (`SEGMENT_RE = /^[A-Za-z0-9._~:-]{1,120}$/`) |
| `partido/<id>` | `{ vista: 'partido', id, canal: null }` |
| `partido/canal/<hash>` | `{ vista: 'partido', id: null, canal: hash }` (`HASH_RE = /^[a-fA-F0-9]{40}$/`, se guarda en minúsculas) |
| `sistema` | `{ vista: 'sistema' }` solo con `import.meta.env.DEV` o `?flag=sistema` / `localStorage['aceneo-flags']` (`lib/flags.ts`) |

Lo que no se entiende → `DEFAULT_ROUTE = { vista: 'agenda' }`. Otros parámetros que viven en la URL y se conservan al navegar: `demo=1`, `q=` (buscar), `pestana=` (biblioteca), `flag=`.

Exportado por `routes.ts`: `type Vista`, `type Route`, `NAV_VISTAS = ['agenda','biblioteca','buscar','ajustes']`, `type NavVista`, `VISTA_TITLE` (`Agenda`, `Biblioteca`, `Buscar`, `Ajustes`, `Partido`, `Sistema de diseño`), `DEFAULT_ROUTE`, `parseVista(value, allowSystem?)`, `parseRoute(search)`, `formatVista(route)`, `searchFor(route, currentSearch)` (devuelve `?vista=…` con `/` sin escapar y el resto de parámetros intactos), `sameRoute(a,b)`, `routeDepth(route)` (partido 10, sistema 11, el resto su índice en `NAV_VISTAS`; decide adelante/atrás), `isNavVista`.

`router.tsx`: `RouterProvider({ children, onBeforeChange?, initialSearch? })`. La ruta vive en `useState` (no en un almacén externo) para que cada cambio vaya en `startTransition` y React lance la View Transition. `navigate(to: Route | string, { replace?, instant? })`: `history.pushState({ aceDepth: n+1 })` (o `replaceState`), `addTransitionType('adelante' | 'atras')` según `routeDepth`, y con `instant` no hay transición (lo usa Ajustes al cambiar de sección). `back(fallback = { vista: 'agenda' })`: `history.back()` si `history.state.aceDepth > 0`, si no `navigate(fallback, { replace: true })`. `popstate` → commit con tipo `atras`. `history.scrollRestoration = 'manual'`. Hooks: `useRoute()`, `usePreviousRoute()`, `useNavigate()`, `useBack()`, `useSearchParam(name): [value, set]` (escribe con `replaceState`, no crea entrada).

### 1.4 El armazón (`app/Shell.tsx`, `app/shell.css`, `app/layout.tsx`, `lib/media.ts`)

**Móvil/escritorio se decide en JS con `useLayoutKind()`** (`lib/media.ts`): `MEDIA.tablet = '(min-width: 768px)'`, `MEDIA.desktop = '(min-width: 1024px)'`, `MEDIA.wide = '(min-width: 1280px)'` → `LayoutKind = 'mobile' | 'tablet' | 'desktop' | 'wide'`. Más: `MEDIA.phoneLandscape = '(orientation: landscape) and (max-height: 540px)'`, `MEDIA.finePointer = '(hover: hover) and (pointer: fine)'`, `MEDIA.reducedMotion`, `MEDIA.reducedTransparency`, `MEDIA.dark`. Helpers: `matches(q)`, `subscribeMedia(q, fn)`, `useMediaQuery(q)`, `prefersReducedMotion()`. El CSS repite las mismas fronteras (768/1024/1280).

`Shell()` calcula:

```
inPartido      = route.vista === 'partido'
dockMounted    = PlayerDock !== null && (inPartido || presence.active)
presentation   = inPartido ? 'stage' : 'mini'
immersive      = presence.immersive || (inPartido && phoneLandscape)
asideAvailable = Aside !== null && (kind === 'desktop' || kind === 'wide')
asideVisible   = asideAvailable && asideOpen           // localStorage 'aceneo-panel' = 'abierto' | 'plegado'
columnVisible  = inPartido && kind === 'wide' && AgendaColumn !== null
miniVisible    = dockMounted && presentation === 'mini'
tabbarVisible  = kind === 'mobile' && !inPartido
```

Árbol y clases raíz:

```

├── a.skip-link «Saltar al contenido» (→ #contenido)
├── nav.rail (Rail, ≥768)

│   │   └── StatusLineHost.stage__status                       (solo inPartido; min-height 44px reservado)
```

- Las vistas visitadas siguen montadas (`Activity`) y conservan estado; el scroll de la página se guarda en `onBeforeChange` (`saveScroll`) y se restaura en `useLayoutEffect` (`restoreScroll`). Tras navegar (no al abrir), el foco va al `h1[tabindex="-1"]` de la vista activa o a `#contenido`.
- Avisos: `setWatching(inPartido)` y `clearStatus()` al salir del partido; `setImmersive(immersive)`.
- Atajos del armazón: `app.ayuda` (`?`) abre la ayuda; `app.buscar` (`/`) navega a biblioteca y `requestFocus('buscar-biblioteca')`.
- `LayoutContext` / `useLayout()` da a las vistas `{ kind, asideVisible, asideAvailable, setAsideOpen(open), columnVisible }`. `useViewSignal()` devuelve una `AbortSignal` que se aborta al ocultarse la vista.
- `shell.css` (variables en `tokens.css`): `--rail-w: 84px`, `--column-w: 300px` (340 ≥1600, 380 ≥2200), `--aside-w: 340px` (380/440), `--tabbar-h: 64px`, `--tabbar-gap: 10px`, `--mini-h: 64px`, `--content-max: 1180px`. Móvil: `.stage[data-presentation='stage']` es `position: sticky; top: 0; z-index: var(--z-sticky)` a sangre (márgenes negativos con `--gutter` y safe-area). Mini: `.dock[data-presentation='mini']` es `position: fixed; z-index: var(--z-mini)`; en móvil ocupa de `safe-left+12` a `safe-right+12` sobre la barra; desde 768 va abajo a la izquierda junto al carril con `width: min(440px, calc(100vw - var(--rail-w) - 32px))`.
